### 3.1 为什么 R1 一次顶针做不了（结构性说明）

一次 Pin 之后，唯一还能当「固定停靠点」的东西只有两类：

1. 顶针在第 1 层补出来的针；
2. 紧贴第 1 层、且**没有被碎晶打断**的普通格（B 的实心段）。

其它所有能当支撑的东西（E 的满高纯晶体柱、B 的晶体桥、A 的临时晶体段）都会在
「E 顶端超限整根碎」时被同一簇晶体的破碎带走。因此每一个「下降通道」的上方都不再
有任何固定材料 —— 落差 ≥ 2 层的普通格只能一路落到**已经落定的那一枚普通格正上方**。

`P.T.T..c`（8 层）的实测正是如此：

```
A = cccTcTc.   （两枚源普通格在 L4、L6，目标 L3、L5）
I（顶针前）= {2,3,4,5}、J = {4,6}
B = TccccT..   N = TTTTPTPT.
Pin → PTT....c   （两枚普通格停在 L2、L3；目标要 L3、L5）
```

第二枚源格在 L6（顶针后 L7）往下落时，B 在它这一层是**晶体桥**（`I` 里的 `{4,5}` 段），
碎晶后连同 E 一起消失，于是它同样没有陪落的普通格。实测两枚普通格都没有停在自己
该停的层：第一枚（目标 L3）一直落到第 1 层的针上方（L2），第二枚（目标 L5）被第一枚
挡住，叠在 L3 —— 这就是「落地栈」现象：**一枚顶针只提供一个停靠层**（针 / 紧贴针的
普通格），第二枚只能叠在它上面。

R1 要清掉必须引入**第二次顶针 / 第二次落地**（多一个停靠层），或按 §15 逐块多刀，
不是把 A、I、J 再调一调就能解决的。

## 5. 结论

1. **已归零。** 旧两段开关 29 例失败（8 层 3、9 层 26）全部被 §17 的三条规则覆盖：
   - **§17.1 R1（16 例）**：`TryBuildConstructedHRuleR1`（`AngleWorkOrder.cs`）——
     A = 目标列整体下移一格；对每颗「正下方为空」的原生晶体，把它下方空段再往下的
     最近一枚普通格提到空段顶端，整段空层填临时晶体。于是每个要下降的普通格都是
     A 里一枚独立的 T，两枚之间由临时晶体隔开（`P.T.T..c`：A = `cTcccTc.`）。
   - **§17.2 R2（11 例）**：同一条下移规则让目标的第 2..m 枚底针原样留在 A 的底部
     （m−1 枚原生针），最后一次 Pin 在 L1 补出第 m 枚；结构性终止条件仍是
     「底针全部就位」。`PP.T.cTc` 的 A = `PccTcTc.`，一次 Pin 得目标。
   - **§17.3 R3（2 例）**：最高晶体以上的 T/P 由已有的「核心 / 尾部拆分」（构造 C：
     先加高托柱、再逐层 Stack）负责，**不参与顶针**。`P.T.T..cP` 的核心是
     `P.T.T..c`（§17.1 覆盖），最后把针堆到 L9。
2. **删除的旧路线**：`TryBuildConstructedHPaper`（§20.3 构造式）、
   「带下降通道扫描」与「下移一格扫描」两个独立候选、以及
   `ConstructHStrictTwoStage` 开关。现在 `TryBuildConstructedH` 只有一条链：
   §0.4 七步 → 失败时退回 §17.1 R1 独立源格。
3. **§0.4 单独口径的验收数**（`SHAPE_TWO_STAGE_AUDIT=1`，3–9 层全量）：
   `3–9 层失败数 = 0 / 0 / 0 / 0 / 0 / 0 / 0`，合计 **0**；
   每层 S 列数 47 / 152 / 476 / 1450 / 4320 / 12646 / 36508。
   代表例（前态 | Pin 后）：
   - `P.T.T..c`：`cTcccTc.|cTTccTTT|cccccccc|TTTTTPTT` → `P.T.T..c|...` ✔
   - `PP.T.cTc`：`PccTcTc.|TTcTTTTT|cccccccc|TTTPTTTT` → `PP.T.cTc|...` ✔
   - `P.T.T..cP`：核心 `cTcccTc..|...` → Pin 得 `P.T.T..c.`，再 Stack 针到 L9 ✔
4. 默认模式（只剩 §0.4 后）数字不变：
   `AUDIT success=2125 failures=0 falsePositives=0`、`LAYERAUDIT 7 = 4320/0`、
