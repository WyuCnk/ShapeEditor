# O-v2：以「碎晶路线」为主的优选算法（2026-11-17）

> 本文替代 §0.11 的 O-v1。**只写规格，不写推导。**
> 依据：本会话实测的 4 个碎晶样例（`T.c`、`T...c`、`.TT.cTT.c`、`T.T.c` 两刀版）
> 与「角工序指标」文档（M1 弱落权重最高）。

---

## 1. 为什么换主角

| 路线 | 弱落 M1 | 刀数 M3 | 辅助列 M4 | 前态规则 |
|---|---|---|---|---|
| **碎晶（构造 D/G）** | **0** | **1** | **2** | 统一：正规核心 + 托柱 + 保险丝 |
| 顶针（构造 H） | 0 | 0 | 3 | **不统一**（N 的针段、BTop 都是按族反推的经验式） |

碎晶路线的**唯一劣势是刀数**（M3=1 vs 0），但 M3 排在 M1 之后，
而顶针路线的规格至今没有通用形式（§0.3.1 的统计：N 连续针段只在 345/974 成立）。

⇒ **优先碎晶；顶针只作退路。**

---

## 2. 碎晶路线的规格（核心）

```
输入：目标列 t（1..cap）
输出：前态 A | S | · | F   （第 3 象限留空）

① 正规核心
   A = 目标列，把「最高晶体以下」的所有空位填成【临时晶体】
   ⇒ A 是紧列，且 c 与 T 交替（实测四例都是这个形态）

② 托柱 S（第 2 象限）
   S = 满高普通格；
   在【每枚被提升的普通格的**源层**】放针（构造 E 的针位——四个基线的针都在源层）
   —— 该格切完要往下落到目标层，落点那一层不能粘连

③ 保险丝 F（第 4 象限）
   F = **紧列到最高锚层**、其上留空；
   在【每个临时晶体段的锚层（最上层）】放一颗晶体
   —— 它把临时段接到刀口另一侧

④ 一刀（构造 D）
   刀口穿过保险丝晶体与临时段的连接；
   临时段整段碎掉，被提升的普通格落回目标层

⑤ 收尾
   构造 C：托柱换成满高普通柱，拆保险丝，清第 3/4 象限
   Target = 左柱 + 目标列 + 右柱（统一形态，消除手性）
```

### 2.1 四个实测样例（回归基线）

| 目标 | A | S（托柱） | F（保险丝） | 刀数 | 结果 |
|---|---|---|---|---|---|
| `T.c` | `cTc` | `TPT` | `c..` | 1 | ✔ |
| `T...c` | `cccTc` | `TTTPT` | `TTc` | 1 | ✔ |
| `.TT.cTT.c` | `cTcTcTcTc` | `TTTPTTTPT` | `cTcTTTc..` | 1 | ✔ |
| `T.T.c` 第一刀后 | `cTcTc` | `TTTPT` | `TTc..` | 1 | ✔（→ `cTT.c`） |

**注意**：`.TT.cTT.c`（9 层）的临时段是**两段不连续**的（`{2,3} ∪ {7}`），
保险丝在两段各放一颗晶体（L1、L3、L7 的 `c`），**一刀同时碎两段** ——
这是顶针路线做不到、而碎晶路线天然支持的能力。

## 3. 顶针路线（退路，规格保持 §0.11）

只在下列情况使用：

```
① 碎晶路线回放失败（刀后不等于目标）
② cap 不足，碎晶的临时段越界
③ 目标本身需要我们保留某颗晶体、而切刀会误伤
```

规格同 §0.11 + §0.3（`I`、`J`、`BTop`、`NTop`）。
**注意其经验式只在部分族成立**（§0.3.1），所以实现必须靠回放验收，不能靠公式保证。

---

## 4. 多刀与交换柱

若一刀不够（落点区间重叠、或上下段落点互相依赖）：

```
按【临时晶体块集合 K】逐块切；每切一块前，若该块在刀口另一侧，
先按 §0.12.2 的五步「交换支撑柱」工序，逐步给出完整四列短代码。
终止条件：K = ∅（不是轮数上限）。
```

---

## 5. 统一的收尾形态（重要）

```
Target = [支撑柱] [目标列] [支撑柱]
```

- 两侧柱都覆盖目标现有高度（构造 C）；
- 这样**不再有手性**：比较、回放、UI 显示都只看中间列；
- 验收改为：

```
Target 的中间列逐格 == 目标
左右两侧柱连续接地、无洞、过五项
```

## 6. 选择顺序（写进代码）

```
① 剥尾（Hc 以上，含针）
② 判定（五项 / 分类 / S）
③ 无晶体 / Simple → 构造 A+C
④ NeedsCrystalBreak：
     a) 碎晶路线（§2）：A=正规核心，S/F，一刀
     b) 顶针路线（§3）
     c) 算法 6 四步（含弱落）
     d) 多刀（§4）
⑤ 接尾（逐层 Stack，先加高托柱）
⑥ 收尾：统一成 左柱+目标列+右柱
⑦ 验收：Gate 四条 + 指标 M1..M7 记录
```

## 7. 补充（2026-11-17）：有些角**没有一刀解**，必须多次切割

用户实测确认：

> `T.T.T.c` **不存在一刀碎晶的解**，必须多次切割碎晶，工序类似 `T.T.c`。

`T.T.c` 的两刀流程（用户给过）：

```
第 1 刀：crCu--Cu:CuCu--Cu:crCu--cr:CuP-----:crCu----
        → cTT.c
交换支撑柱（五步，见 §0.12.2）：
        → crCu--Cu:CuCu--P-:CuCu--Cu:--P---Cu:crCu--Cu
        → 旋转 → CucrCu--:P-CuCu--:CuCuCu--:Cu--P---:CucrCu--
        → 再换 → Cucrcr--:P-Cu----:CuCu----:Cu------:Cucr----
第 2 刀：→ CuCu----:P-------:CuCu----:Cu------:Cucr----
        → T.T.c
```

⇒ **「多次切割」是独立的一档**，不能因为「一刀不成」就直接跳到算法 6 的弱落。

### 7.1 修正后的路线优先级（**以本节为准**）

```
① 碎晶·一刀（§2）
② 碎晶·多刀 + 交换支撑柱（本节）
③ 顶针（§3）
④ 算法 6 四步（含弱落）
```

**理由（按 M1 排序）**：

| 路线 | M1 弱落 | M3 刀数 | 结论 |
|---|---|---|---|
| 碎晶·一刀 | 0 | 1 | 最优 |
| 碎晶·多刀 | **0** | 2–3 | 次优（M1 仍是 0） |
| 算法 6 | **2** | 0 | **最差**（弱落权重最高） |

`T.T.T.c` 当前实现走的是算法 6（2 次弱落），按上表应改成**多刀**。
