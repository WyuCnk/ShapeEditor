```

原因：

**请裁决**：
- (a) 以指标为准 ⇒ 这 62 列回到旧 §15 多刀；
- (b) 以路线顺序为准 ⇒ 保留新路线，并在文档注明「M5 的代价是五步换柱的规范成本」；

### Q-3「能抬多高抬多高」的口径

当前实现读作：**「保持 A 为紧列 + 满足 P1 的前提下，抬到不能再抬」**。

**请确认**并在 §0.12.3 写明：
```

且必须保证：A 仍是紧列（c/T 交替）、P1 成立、临时晶体段完整

## 四、实现侧已确认的事实（供 Core 引用）

1. **`K` 驱动多刀**：每轮取「当前最上面的一块」→ 五步换柱 → 一刀 → `K = K \ {块}`；每刀后检查块数 −1（防原地打转）。
2. **换柱只按「下一刀那一个块」算**：新托柱的针与新保险丝都只针对该块，否则其余块会被同一刀误切、失去刹车。
3. **`T.T.c` 序列**与用户给的五段短代码**逐字一致**（差异仅坐标系：实现按「先旋转后装柱」的文字顺序）。
4. **`T.T.T.c`**：3 刀、2 轮换柱（10 个换柱步）、弱落 0；M1–M7 = `0/0/3/2/5/16/19`。
5. **抬升审计**：3–6 层 309 条前态，P1 违规 0、抬升上界违规 0。
