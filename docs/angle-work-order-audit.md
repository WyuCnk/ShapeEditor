## 1. 方法与结果

对长度 3–6 的全部列（字母表 `.` `T` `P` `c`，共 5460 个）：

1. 五项条件 → 合法性；
2. `五项 ∧ (D∨F)` → n = 4 的 S；
3. 每个 S 列调 `AngleWorkOrderBuilder.Build(shape, 0, len)`。

```
合法列              2126
  其中 S            2125
  其中合法非 S          1    ← cT.T.T.c
S 列工序生成成功      2106    （99.1%）
S 列工序失败            19
```

**生成失败 = 19 个，全部集中在两个未实现的特性上。**

## 2. 失败的 19 个，分三族

### 族 A（16 个）：最高晶体上方有「尾部」材料，未处理

```
.T.cT   .T.cP   .T.cT.  .T.cP.  .T.c.T  .T.cTT  .T.cPT  .T.cTP
.T.cPP  ..T.cT  ..T.cP  P.T.cT  P.T.cP  .T.ccT  .T.ccP  .T.ccP
```

共同特征：

| 项 | 值 |
|---|---|
| 有尾部（最高晶体之上还有 T/P） | 1 |
| D | True |
| F | False |
| Construction | None（没选到任何构造） |

**报错归因错了**：现在报「构造 G 需要晶体塔至少三连晶」，但真正的问题是
**算法 3 第 3 步「接回最高晶体以上的无晶体尾部」没有实现**（构造 C 逐层追加）。

证据：`.T.c`（无尾部）能过，`.T.cT`（同样的核心 + 一个尾部 T）不能过。
核心部分的判据与构造都是对的，缺的是「把尾部接回去」这一步。

### 族 B（2 个）：底格有材料时，算法 6 的「底块提升」没做

```
T.T..c   → 选了构造 H，但 H 的顶针要求目标底层是针或空，实际是 T
P.T..c   → 底格是针，本该走算法 5，却选了构造 H
```

- `T.T..c` 属于「D 成立 + 底格是普通格」⇒ 算法 6 应先做**底块提升**
  （把最下方连续普通块抬高，清出最底两层），再交给构造 H；
  现在直接把目标交给 H，触发 H 的前置条件失败。
- `P.T..c` 底格是针 ⇒ 分档**应先判「底格是针」走算法 5**（§2 的顺序约定），
  现在落到了算法 6 的 H 分支。

### 族 C（1 个）

```
.T.cTc   → FillBreak 把临时晶体删错层：第 4 层期望晶体，实际空
```

## 3. 另一个判定问题（不是覆盖率）

```
cT.T.T.c   五项 ✔   D ✘   F ✘   ⇒   合法但【不是 S】
```

角工序应报「**不可制作**」（S 不成立），现在报的是
「未覆盖：构造 G 需要三连晶…」。

§6 第 6 条明确要求区分「未覆盖」与「不可制作」，这里没做到。
全 ≤6 层的合法非 S 列只有这 1 个，正好可以用来钉这条判定。

## 5. 建议修法（按性价比排序）

1. **拆核心 / 尾部**：`Build` 先把列拆成「核心（最高晶体及以下）」与「尾部（以上）」，
   核心走现有流程，最后用构造 C 逐层追加尾部。
   → 一次修 16 个，覆盖率 99.1% → **99.9%**。
2. **算法 6 先做底块提升**：D 成立且底格非针时，先把最下方连续普通块抬高、
   清出最底两层，再进构造 H → 修 `T.T..c`。
3. **分档顺序**：底格是针时优先算法 5 → 修 `P.T..c`。
4. **判定收尾**：S ✘ ⇒ `NotProducible`（不要落到 Uncovered）→ 修 `cT.T.T.c`。
5. `.T.cTc` 的 FillBreak 删层问题（单例，可最后看）。

---

## 6. 一句结论

主智能体的实现基本达标（99.1%），**剩下的不是「算法没写」，而是两个明确的实现缺口**：
**尾部接回**与**底块提升/底针分档**。加上判定收尾，n = 4 就可以宣布覆盖完整。
