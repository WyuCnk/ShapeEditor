仓库在 `D:\ShapezEditor`。请先阅读：

## 二、已知且正确的部分

- 图形：8 象限、9 层的环形竖式图；象限 1 = 东北，顺时针递增。
- 稳定性：执行一次下落后图形与原来逐格相同。
- 交换方向 = 轴 × 左切点 × 右切点，共 `n/2 × (n/2−1)²` 个。
- 半边图形：保持原象限数，只保留该半的列。
- 柱子：`Cu`（普通形状），补满所有层。
- 制作路径工序链：四个带柱子的半半边 → 交换得两个半边 → 交换得图形 → 顶针与堆叠。

## 三、需要你定死的四件事

### 1. 四个带柱子的半半边，柱子放在哪个象限

已给的两个实例（方向 `(1+2)+(3+4)`）：

```
第一个（柱子在第 8 象限）：
Cu------------Cu
--------------Cu
crCu----------Cu
cr------------Cu
crCu----------Cu
--------------Cu
--cr----------Cu
--cr----------Cu
--cr----------Cu

第二个（柱子在第 5 象限）：
--------Cu------
--------Cu------
----Cu--Cu------
----Cu--Cu------
----Cu--Cu------
--------Cu------
----CuCuCu------
------CuCu------
----CuCuCu------
```

请给出通用规则：对任意轴、任意切点，四个子图形的柱子分别落在哪个象限（用公式表达，例如 `(axis + split + k) mod n`）。

### 2. 交换前的旋转量

已给实例（8 象限，方向 `(1+2)+(3+4)`，最后一步两个半边交换）：

```
C12C0000 → 0C12C000     （旋转 1 个象限）
C34C0000 → 000C34C0     （旋转 2 个象限）
```

请给出通用规则：每次交换前，两个输入各自旋转多少个象限（与轴、切点、半边序号的关系）。

### 3. 切割与交叉拼接

实例中：

```
0C12C000 切割 → 0C12 | C000
000C34C0 切割 → 000C | 34C0
交叉：0C12 + 34C0 = 0C1234C0
      C000 + 000C = 000CC000（废）
```

请明确：切割线是否总在"两根柱子之间"的中点、拼接时哪一半放左哪一半放右、是否还需要再旋转。

### 4. 成功与废料的判定

- 一次交换有两个输出，是否"任意一个等于期望"即成功？
- 中间步骤（半半边 → 半边）的期望图形如何确定？
- 顶针与堆叠插在哪一步之后、作用在哪个图形上？

## 四、已发现的实现缺陷（供你判断哪些规则被我理解错了）

- `PillarShape` 给每个子图形补了**两根**柱子，位置取"半边两侧邻列"。
- 交换没有旋转步骤。
- 在上述 8 象限样例上，轴 0 的 9 个方向被全部判成合法，而按预期应该都不是合法（至少两个带柱子半半边应判不稳定）。

## 五、交付格式

请输出：

1. **伪代码**：`BuildPillarHalfHalves(shape, axis, leftSplit, rightSplit) → 4 个图形`
2. **伪代码**：`Exchange(a, b, rotationA, rotationB) → (out1, out2)`
3. **伪代码**：`ParseProductionPath(shape) → 路径 | 失败`，含遍历顺序与剪枝
4. **样例**：至少 3 组「图形 + 方向 → 每一步的中间结果」，用短代码表示，可直接写成测试
5. **反例**：至少 2 组确定不可制作的图形，说明被哪一步否决
