## 记号

- 6 象限，从 1 到 6 环形排列。
- `C` = 满层 Cu 柱子（普通形状，补满原图总层数）。
- `0` = 空列。
- 数字 = 该象限在目标图形中的内容。

## 已确认的样例

目标：6 象限图形 `123456`（1—6 各占一列）。
交换方向：`(12+3)+(4+56)`

四个带柱子的半半边：

```
C12000
0003C0
0C4000
00056C
```

两次交换（同侧配对）：

```
C12000 + 0003C0 = C123C0 + 000000（废）
0C4000 + 00056C = 0C456C + 000000（废）
```

**这里的"交换"结果需要再经过旋转才能对齐**：

```
C123C0 旋转 → 123C0C
0C456C 旋转 → C0C456
```

最后一次交换：

```
123C0C + C0C456 = 123456 + C0CC0C（废）
```

得到目标图形 `123456`，废料 `C0CC0C` 舍弃。

## 从样例中读出的要点

1. **交换之后存在旋转步骤**（`C123C0 → 123C0C`、`0C456C → C0C456`），旋转规则待明确。
2. 交换的两个输出中一个是所需图形，另一个是废料；样例里 `000000` 作为废料。
3. 柱子会被带进中间结果，最终以废料形式留在另一输出里（`C0CC0C`）。
4. 目前不清楚：旋转是算法的一部分，还是手工对齐的示意；旋转几次、按什么规则。

## 旋转与结晶（后续完整制作路径会用到）

### 旋转

短代码象限编号：**1 = 东北象限**（中轴线右上方），之后按顺时针依次 2、3、4……

| 操作 | 含义 |
| --- | --- |
| 顺转一个象限 | 所有列按顺时针移到下一象限（等价编辑区「右移」） |
| 逆转一个象限 | 所有列按逆时针移到上一象限（等价编辑区「左移」） |
| 反转 | 顺转 n/2 个象限（对角交换） |

实现上可复用 `ShapeDocument.MoveLeftCircular` / `MoveRightCircular`。

### 结晶

输入一个颜色代码（如 `r`），把图形里**所有空位与顶针**替换成该颜色的晶体，其他单元格不变。

用途：制作路径末段把框架结晶成目标晶体结构。
## 补充样例：交换的旋转与切割（8 象限，方向 (1+2)+(3+4)）

### 最后一步：两个半边交换

```
输入（两个半边，两端各一根柱子）：
  C12C0000
  C34C0000

各自旋转：
  0C12C000
  000C34C0

各自切割：
  0C12 | C000
  000C | 34C0

交叉拼接：
  0C12 + 34C0 = 0C1234C0   （目标图形）
  C000 + 000C = 000CC000   （废料）
```

要点：

1. **交换前要先旋转**，两侧旋转量可能不同。
2. **半边两端各有一根柱子**。
3. 切割后交叉拼接，柱子残留在结果两端，成为废料。

### 带柱子的半半边（同一方向）

```
第一个：Cu------------Cu
        --------------Cu
        crCu----------Cu
        cr------------Cu
        crCu----------Cu
        --------------Cu
        --cr----------Cu
        --cr----------Cu
        --cr----------Cu

第二个：--------Cu------
        --------Cu------
        ----Cu--Cu------
        ----Cu--Cu------
        ----Cu--Cu------
        --------Cu------
        ----CuCuCu------
        ------CuCu------
        ----CuCuCu------
```

- 柱子**补满所有层**。
- 第一个的柱子在第 8 象限，第二个的第 5 象限（按这两个字符串实际内容为准）。
- 这两个带柱子的半半边**都应当判定为不稳定**；当前实现在这个图形上把轴 0 的 9 个方向全判成合法，结果错误。

### 当前实现的问题

- 以上两点导致稳定性判定过宽。
